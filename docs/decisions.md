# validx 架构决策记录(ADR)

> 状态说明:**已接受**(按全自动迭代授权,无需逐项确认)。

## ADR-001:tag 驱动,规则声明在字段旁

- **决策**:`validate:"required,min=3"` 声明式校验;
- **影响**:规则与字段就近,可读性最佳。

## ADR-002:规则预编译缓存

- **决策**:类型解析结果缓存于 sync.Map,非法规则不缓存;
- **影响**:热路径零重复反射,配置错误每次暴露。

## ADR-003:格式规则复用标准库解析器

- **决策**:email→net/mail、url→net/url、ip→net.ParseIP、
  regexp→regexp 预编译;
- **影响**:零第三方,语义权威。

## ADR-004:错误统一 errx 聚合

- **决策**:多字段失败 `errx.Join`,单字段透传;
  错误携带 field / rule 字段;
- **影响**:HTTP 层可直接消费,与生态一致。

## ADR-005:实例级自定义注册,无全局状态

- **决策**:`RegisterValidation` 在 Validator 实例上注册;
- **影响**:测试隔离与多租户安全。

## ADR-006:嵌套与 dive 语义

- **决策**:结构体字段自动递归;slice/map 元素需显式 `dive`;
  空指针/空容器由 required / omitempty 语义处理;
- **影响**:显式优于隐式,避免 validator 式魔法。

## ADR-007:规则顺序执行,首败即止

- **决策**:字段规则按 tag 顺序执行,首个失败即记录并停止;
- **影响**:错误确定性强,消息可预期。
